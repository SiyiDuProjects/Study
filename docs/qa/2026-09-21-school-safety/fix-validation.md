本文件承接同目录 `report.md` 的修复前审查，不覆盖原始失败证据。所有教师重交要求的回归场景均为合成测试；不代表当前真实课程出现教师退回重交。

## 实现与本地验证

| 原问题 | 修复 |
| --- | --- |
| F1 缺交被 graded / overdue bucket / Planner 勾选掩盖 | overdue 从全量作业和自己的提交状态计算；Planner 不使用上游 incomplete 筛选；保留缺交、重交、评分、提交和人工勾选的独立字段；逐页输出课程、筛选及查完标志 |
| F2 教师重交标记丢失 | 列表、详情、历史及 MCP schema 保留 redoRequest 和额外尝试次数；缺交、正常第二次提交和教师重交要求分开解释 |
| F3 空记录和身份矛盾被当成学校事实 | 校验作业/课程/学生身份、必需 ID、关键布尔值和历史结构；无法识别的空记录报错，未知状态保持 unknown |
| F4 lockAt 为空即推断能补交 | 保留用户锁定、锁定说明及次数限制；Skill 明确信息不足时资格未知，技术可提交不等于教师接受迟交 |

| F6 URL 资源定位参数被全部抹掉 | 只保留受控的数字资源定位参数；其余参数/片段清除并提示链接内容省略 |
| F7 嵌入资料静默消失 | 禁止执行嵌入内容，同时提示未读；学校文件嵌入保留安全引用 |
| 追加：正文中的签名 URL | 可见文本、链接文字和图片替代文字也清除 URL 的能力参数，避免只清理 href 的缺口 |

## 验收边界

- coverage.queryExhausted 只描述当前课程、当前筛选的读取是否耗尽；不是“所有学校要求均已查清”。跨课程清查仍需按 Skill 遍历，并单独报告公告、消息、LearningX 和课堂资料的范围。
- overdue 保留逾期且没有本人提交证据的可疑项；缺少提交时间或已有分数不能单独证明未交，应复核自己的提交类型和详情。
- 回归测试和结构化工具调用不等于所有模型回答均正确；线上部署、真实作业读取和 ChatGPT 刷新验收须分别记录。
- 未提交作业、未发消息、未改学校状态、未启动录音。
