## 为什么以前慢且容易找错位置

1. 我把本地插件安装、MCP 服务发布、线上工具快照刷新当成了一个交付步骤；.app.json 只关联远程 App，并不上传本地 Skills。
2. 工作区有未提交且已部分上线的改动；仅看 git dirty 或 UI 版本号无法判断线上内容。
3. 发布依赖多个带日期的临时脚本与旧 clone，其中部分文件仍检查已废弃的 sessions/hits 字段，文档还遗漏环境变量。
4. Core/Record 的共享接口缺少兼容过渡，原方案无法安全分步切换；授权组件 bootstrap 也可能在没有实际组件文件时报告安装成功。
5. 并行线程同时更新同一份 Skill 和 generated catalog，校验期间的源码变化会使结果失效。本轮已协调冻结并统一发布；其余线程只保存明确分工的账号 Skill。

以后从 ../release-workflow.md 开始，运行 npm run release:status 查上次回执，再运行 release:check 和 release:prepare。修改只回到 canonical 目录，不编辑 cache、generated catalog 或发布副本；报告上线时必须有对应服务版本和真实读取证据。
