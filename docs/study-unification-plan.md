# Study 合并与私有开发者连接迁移计划

状态：已获授权，实施中；本文不代表已经迁移或创建新连接。

## 目标与固定地址

维护一套 Study 代码：共享 Canvas 能力，分别保留 Berkeley 与 Hanyang 的平台配置和扩展；在 ChatGPT 网页开发者模式创建一个仅自己使用的新 Study 连接。

使用一个 ChatGPT 账号、一个 Study 插件，在插件内连接两个学校账号；不是创建或切换两个 ChatGPT 原生账号。

已确定长期固定以下地址：

| 用途 | 地址 |
| --- | --- |
| Study 网站、账号管理与认证 origin | https://study.siyidu.com |
| ChatGPT MCP 连接 | https://study.siyidu.com/mcp |
| 已有课堂记录网站 | https://lecture.siyidu.com |

网站页面与后台部署位置可以后续变化。长期保持 MCP URL、认证 issuer、WebAuthn RP ID 及账号 profile 标识稳定。兼容的功能更新不要求重建连接；工具元数据变化需要刷新并验证，新增权限可能需要重新授权。

## 实施顺序与验收

### 1. 保存基线并验证双账号机制

- 保存最新源码、构建、测试和发布清单的对应关系；读取 Berkeley 当前实现及发布状态。
- 为新架构更新单学校仓库边界说明；保留现有读写授权限制，不新增学校写操作。
- 用最小测试实现验证一个公共工具、一个平台专属工具、稳定 profile 身份及两个独立授权。
- 在实际 ChatGPT 网页开发者模式验证账号标签、两种连接顺序、交替调用、重连以及工具元数据发现行为。
- 不依赖未经验证的按账号隐藏工具机制。若客户端展示统一工具集，提供明确的适用范围与能力查询，并在服务端强制校验。

验收：明确实际客户端支持行为，确定账号绑定和工具呈现方案；不以 MCP 规范允许替代 ChatGPT 实测。

### 2. 合并公共实现与平台扩展

- 以刚完成修复的 Study Canvas 实现为基础，逐项吸收 Berkeley 差异，不以覆盖文件方式合并。
- 公共部分包括读取、分页、结果规范化、文件访问、错误处理、工具定义与回归测试。
- Berkeley 模块保留其学校 origin、能力和权限；Hanyang 模块保留 LearningX、课表、学校字幕等扩展。
- 保持同一公共工具的输入输出契约稳定，平台特有含义不强行等同。
- 保留已评分缺交、重交、未知状态、锁定信息、公告日期和资料链接的近期修复及测试。

验收：一份公共实现覆盖两校测试；平台扩展独立；日期与时区、课程 ID 和分页状态不混用。

### 3. 账号与数据归属迁移

- 每个学校连接具有独立稳定的 profile ID，OAuth 授权绑定具体连接；平台由服务端认证结果决定。
- 不自动合并两个学校账号的真实身份或档案所有权，不以同名、邮箱相似或课程数字 ID 判断同一对象。
- 改造当前全库单 Canvas 连接约束；课程、缓存、下载授权和游标按连接归属。
- 将 Lecture 的唯一汉阳账号假设改为明确授权检查，首期仍只向原有授权账号开放现有档案。
- 在数据库副本验证用户映射、加密凭据绑定、课程与转录关系；规划原账号验证和新域名通行密钥登记流程。
- 保留 Sites D1 和原有转录；Core 继续是学校凭据接入与保存边界，不向 Record 传递 PAT，不保存原始课堂音频。

验收：跨账号、跨学校的 ID、游标与文件链接误用被拒绝；原档案完整；恢复方案经过副本验证。

### 4. 统一网站与按服务发布

- Study 首页、登录、连接和账号页面使用统一品牌，清楚显示学校、身份、授权和可用功能。
- 保留独立学校连接，避免设置全局“当前学校”而导致并发请求串账号。
- Lecture 保持现有固定域名和部署方式；只修改实际需要配套调整的权限和内部契约。
- 沿用并完善 Core-only 发布；Record 与共享契约改变时才执行对应的配套发布。
- 发布自动串联相关检查、版本记录、备份、健康验证及回滚；保留已有上线证据标准。

验收：纯 Core 修复不要求重新部署无变化的 Record；发布范围与依赖变化一致。

### 5. 创建新连接并迁移使用入口

- 使用固定 https://study.siyidu.com/mcp 在目标 ChatGPT 网页开发者模式创建新 Study 连接，不走公开插件商店审核。
- 分别授权两个学校账号，检查工具元数据、账号身份和权限。
- 更新仓库插件说明与远端 App 映射；新 App ID 以实际创建结果为准。
- 检查并迁移原生 Skills 与服务器 Skill 内容，保留近期可靠性修复；检查现有定时提醒是否引用旧连接，按原意接到新连接，避免重复创建提醒。
- 验证共同工具、Hanyang 专属工具、文件读取、课堂档案和跨账号连续对话；补做基线尚未覆盖的自然语言端到端验收。

验收：目标网页账号实际可用；本地文件修改、缓存安装或服务器自测均不替代该验收。

### 6. 切换与旧入口退出

- 新连接验证通过后再转移日常使用，旧服务在过渡期间冻结为回退版本。
- 普通网页跳转与 MCP/OAuth 兼容分开处理，不用统一重定向替代认证迁移。
- 清点旧连接、Skills、提醒和链接依赖后，再停用旧入口与重复服务。
- 数据库变更后回滚须考虑新增数据与 schema 兼容性，不能直接用旧备份覆盖期间产生的数据。

验收：只有一套活跃开发、测试与发布代码；旧副本仅用于有限过渡与恢复。

## 首次切换前必须完成与可以后续调整的内容

必须完成：固定 MCP/认证地址、账号与数据隔离、现有功能迁移、近期 bug 修复保留、凭据迁移方案、ChatGPT 双账号实测及回滚。

可以后续调整：页面视觉、导航细节、描述与默认提示、新增只读能力、性能与缓存、平台模块内部实现。工具契约变化仍需刷新/兼容，权限变化仍需重新授权；地址固定不代表其他修改完全没有迁移成本。
