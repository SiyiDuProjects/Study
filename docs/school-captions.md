# 学校字幕自动接入

Study Core 进程启动后，后台自行读取 Hanyang 在读课程及 Weekly Learning。Record D1 的课程缓存和默认同步设置由服务间请求初始化，用户从未打开 Record 网页也能运行。新课程默认检查学校转录；用户明确关闭的课程不会自动重新开启。发现周期为 5 分钟。

Weekly Learning 返回 `translive.id`、`translive.viewerUrl` 和独立的 `moduleItemId`。学校来源不复用 Canvas 出勤条目 ID，也不把转录入口中的分钟数当成视频秒数。

每个入口先核对课程、模块、韩语及普通查看权限，再接学校 viewer Socket.IO。首次连接和重连均读取本节完整历史。句子以学校的 `order` 为稳定标识，合并半句、定稿、后处理修正和已有中文译文；不发送录音控制、音频、语言订阅或强制生成翻译事件。中文已有历史每 5 秒刷新；没有学校译文时保留原文并明确显示等待。访问受限时保存课程同步错误，不绕过权限。

Core 把变化的句子按顺序、按大小分批写到 Record 的独立内部接收接口。它使用既有 Core→Record 服务凭据，PAT 仍只在 Core。D1 保存原始学校时间、整节历史、明确的 `hanyang-translive` 来源及查看地址；不保存原始音频。重试不会生成重复句子，断流不删除已有字幕。

网页复用现有字幕显示、字号、韩文开关及记录页。麦克风录音和学校网络字幕只更换输入来源。网页每 2 秒读取最近三句，完整历史仍可在记录页或现有 Lecture MCP 中分页查询。学校来源不能接管麦克风写入租约，也不会阻止新建自己的录音。

部署先更新兼容的 Record Worker，再启动 Core 后台接收。Core 候选容器使用 `STUDY_BACKGROUND_JOBS=off`，避免候选健康检查触发生产同步。Core 回滚可保持新版兼容 Record，保留全部已接收字幕。旧 MCP 读取不携带来源能力头时，响应仍使用旧结构；新 Core 用 `X-Study-Lecture-Source: school-v1` 接收来源字段。

当前接入依赖学校 viewer 的实际权限和保留期限。未开放、已关闭访问或需要额外身份/密码的历史入口，不会被描述为已同步。
